# Lifecycle boundaries

- `ExperimentManager` owns matrix execution and persists redacted experiment records. Legacy `status` remains the execution lifecycle. Derived `coverage` counts cells by state and `outcome` distinguishes full success, partial completion, failure, cancellation, and work in progress.
- Cancelling an experiment requests a stop after the current cell; it does not claim in-flight provider work stopped. The request is persisted. On restart an in-flight cell is not replayed, and an accepted cancellation also cancels remaining queued cells. If a cell was in flight, queued work cannot be resumed because the old provider work may still be running. Previously saved interrupted records with the known in-flight marker are also blocked. Queued cells remain resumable when the supported recovery record has no unresolved in-flight cell.
- The Studio's playback state is separate from experiment execution and transport. Recorded replay plays saved frames without launching a model or simulation. Stop Playback is not Stop Experiment. A manual attempt selection invalidates older trace, score, snapshot and model-interaction responses; later live score/trace events do not replace that selection. Playback controls also prevent a pending manual trace from overriding a later play/pause decision.
- If an in-process launch task is cancelled, current and late subscribers receive a terminal interruption error, not a successful `run_finished`; external provider work may still be running. An experiment observing this event marks the current cell failed, leaves later cells queued, and stops scheduling. Its normal resume path is disabled because termination of the external work is not established. These in-memory launch events are not durable across a server restart.
- If the experiment scheduler itself is cancelled, it records the interruption even if its coroutine never started. An in-flight cell is failed with an unknown external outcome, and queued-cell recovery is disabled; without an in-flight cell, the previously supported queued-only recovery remains available. An exception during launch or observation takes the same conservative in-flight path. An accepted cancellation still cancels queued cells. This does not stop or reconcile provider work.
- Run traces, scores, experiments, and exports have distinct persistence/availability boundaries. If a launch is no longer live and has no parent trace, Studio can open a saved attempt for read-only review without restarting work. Its live execution outcome remains unknown. Persistent parent launch status and real provider cancellation remain separate work; the experiment outcome fields do not guarantee complete artifact delivery.

Inspect `/api/experiments` and `/api/experiments/{id}` for outcome, coverage, and cancellation intent. `backend/tests/test_experiments.py` covers mixed outcomes and restart; use mock providers for deterministic checks. Hardware and live-provider behavior remain outside those tests.
